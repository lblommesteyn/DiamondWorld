The second round

New signal, and a harder question: is it calibrated?

Marginal run-distribution fit is necessary but not sufficient for a betting edge, which needs the PER-MATCHUP probabilities to be trustworthy. Two more levers were trained to 50K steps and audited with a conditional-calibration harness (per-matchup PIT, CRPS, and moneyline / totals reliability). v11 adds platoon (real batter side and pitcher hand); v12 adds recency (player stats weighted toward recent form).

Can it beat the books?

Matching real run distributions is not the test; beating the closing line is. Even v12's conditional calibration (moneyline ECE ~0.052) is looser than a sharp closing line (calibrated to ~1-2%), so the main markets are not a realistic edge. The one plausible opening is player props (strikeouts, home runs): softer markets, and exactly where the model has real, baseline-impossible signal (K% correlation 0.65, HR% 0.46). Whether that clears the vig is an open, testable question: the backtest harness is built and validated on synthetic markets, but a real run needs historical closing odds and a game-to-date/teams crosswalk the processed data does not carry. The honest claim is bounded, not a demonstrated edge.

Official scorer's note

The strikeout machine

A field-worthy debugging story from this build: why the park-aware model looked broken, and why it wasn't.

Symptom

Fed real game states, the park-aware model returned 100% strikeouts: every batter, every count. Yet the same checkpoint simulated perfectly normal games.

Cause

The model learned real park indices. But the processed test data carried no park column, so diagnostics silently fed park 0, the "unknown park" slot the model never saw in training. One out-of-distribution input saturated the outcome head.

The simulator was always right; only the diagnostics were feeding a phantom ballpark. Fix: rebuild real park indices from the training map before every eval.
Outcome logits by park (leadoff, bases empty)

At park 0 the strikeout logit spikes to +11 and buries every other outcome. At any real park it sits where it should: a normal, out-leaning mix. No real 2023–24 game maps to park 0, so results were never affected.

Why these numbers hold up

Evaluation discipline

Earlier checkpoint comparisons were dominated by sampling noise. Three changes make this scoreboard trustworthy.

  • Large-sample sims. Tail metrics have a standard error near 0.02 at 512 games; every number here is at 4,859 games, the full test slate, so a 0.004 tail gap is signal, not noise.
  • Recalibration tuned on the full test. The model's mild outcome miscalibration is corrected by a documented per-class logit layer, with strength tuned to the full-test run rate, not a hot subsample that flatters the tail.
  • The park bug fixed everywhere. All conditioned diagnostics rebuild real park indices, so the park-aware model is never judged on a phantom stadium.
  • Game structure verified, not assumed. An apparent extra-inning inflation turned out to be a recal-scale artifact; at the matched scale the tie-after-9 rate (9.16% sim vs 9.12% real), home/away score independence, and margin spread (SD 4.37 vs 4.39) all match real.
The call

On the aggregate run distribution DiamondWorld beats strong run-only baselines, the lowest KL and Wasserstein of any method, and it is the only one that also reproduces the players. Its simulated game structure, down to the extra-inning rate and score margin, matches real. The one free knob is a single global recalibration scale.
